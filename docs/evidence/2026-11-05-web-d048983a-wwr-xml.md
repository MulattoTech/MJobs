## Reproduced behavior

A tiny synthetic WWR RSS response declared an internal entity. The unchanged
adapter expanded it into a job title and reported HEALTHY. The connected
regression then demonstrated that a DTD-bearing document could persist a new
synthetic job. No resource-exhaustion payload, actual provider attack, external
DTD request, user resume, credential or personal data was involved.

The transport's five-megabyte input limit does not itself prohibit XML entity
expansion. This finding does not claim that the runtime's separate Expat
amplification protections were bypassed.

Unsupported encoding declarations also escaped the adapter's fixed error
classification: an unknown codec raised LookupError, and unsupported UTF-7
raised ValueError. These are parser-boundary errors, independent of network
availability or local cancellation.

## Change

- Use a custom standard-library TreeBuilder whose documented doctype event
  raises a fixed ParseError. DTDs are refused for UTF-8, UTF-16 and Latin-1
  input without relying on an encoding-sensitive byte substring scan.
- Convert parser and encoding errors into the existing
  `SOURCE_PAYLOAD_INVALID` category and source-health state.
- Preserve predefined/numeric XML entities, supported encodings, ordinary
  comments and CDATA containing declaration-like text.
- Preserve the existing HTTP origin, redirect policy, response limit,
  cancellation/deadline precedence, resource cleanup and retry machinery.

The standard-library extension point is documented at
[TreeBuilder.doctype](https://docs.python.org/3/library/xml.etree.elementtree.html#xml.etree.ElementTree.TreeBuilder.doctype).
No new dependency, schema, shared collector, transport, worker or configuration
change is required.
