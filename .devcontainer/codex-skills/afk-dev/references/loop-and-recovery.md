# Fresh-context loop and recovery

`python <this-skill-dir>/scripts/afk_loop.py run --project <root> --goal <statement> --model <available-model> --effort <supported-effort> --verify '["python","-m","unittest"]'` starts a fresh `codex exec` per iteration. Use `--goal-file` for long goals and `--resume` after interruption. `--max-iterations 0` removes an arbitrary ceiling; circuit breakers remain. `status` and `--dry-run` inspect without starting Codex.

The runner uses supported `codex exec` flags observed by `codex exec --help`: `--approve-for-me`, `-C`, `--json`, `--output-schema`, `-m`, and `-c model_reasoning_effort=...`. It never uses the dangerous sandbox/approval bypass. Each iteration receives `$afk-dev`, the state root, iteration, and changed condition. It rereads project instructions and current git/state rather than inheriting transcript text. JSONL is redacted before durable storage.

`goal.json` defines acceptance and `verificationCommands` as argv arrays. Each acceptance, CI, or browser obligation needs a `verificationCommand` argv array and recorded evidence before the outer runner can mark it complete. CI evidence must match current HEAD; browser evidence must match the current source fingerprint. A model's `complete` report triggers independent fresh commands; failure or no oracle prevents success. The runner holds an OS owner lock, pins the goal contract across iterations, and rejects a changed contract. `--browser off` or `--ci off` is passed to each child and forbids that class of action for the run.

Before rerunning a deterministic failure, prove a material change: code, justified fixture, environment, dependency, or discriminating instrumentation. Repeated unchanged fingerprints escalate strategy and eventually stop. Three stagnant or false-completion iterations trigger decomposition or alternate-path review, then stop if unchanged. Rate limits use bounded persisted backoff. External blockers stop with the precise missing condition. A stopped run remains resumable; never reset, clean, or discard a dirty repo during recovery.

The iteration result supports `status=handoff` for a brief terminal or conversation transfer where the user wants work to continue. The runner records a handoff event, retains its owner lock, and prompts the next iteration to reconcile the new session and active ownership. This status keeps the existing runner as owner; it does not transfer mutation authority to a new process or terminal. A handoff is not progress by itself and remains subject to the stagnation circuit breaker. Use `status=paused` only for a genuine user request to stop work; it ends the runner and releases its lock. Use `status=blocked` for an unmet external prerequisite. Do not relabel a credential, permission, or safety blocker as a handoff.

At startup, an `inFlight` marker means the prior iteration may have stopped mid-action. Inspect git status, relevant child processes and durable evidence, preserve partial work, and resume the earliest incomplete item. Do not count command launch, a click, or a CI rerun as progress without changed postcondition evidence.
