# Orchestration

The root owns goal, queue, state, integration, and final verification. By default only one agent mutates a shared checkout. Dispatch bounded independent investigation, test analysis, CI log inspection, browser evidence, and review in parallel when it improves speed or independence. Give children exact questions and evidence paths, not a giant transcript. Do not spawn another worker for an already answered question.

Two implementation writers may run concurrently only in isolated worktrees with disjoint ownership and an explicit integration owner. Before merging changes, destructive tests, release actions, or final verification, reconcile workers and ensure mutating children are quiescent. Review child proposals against tests and project authority; a child declaration is not proof. If a child patch breaks a focused test, reject integration, record the failed strategy, correct it, and verify independently.

A terminal or conversation handoff does not itself cancel the root's active goal or interrupt workers. Retain the current owner while bounded work completes. Before transferring mutation ownership, inspect active agents and locks, establish the new session's identity and project authority, and ensure the old owner is quiescent. If that cannot be established, continue only independent read-only work.

Select models from the currently available runtime. Use an efficient compatible model for bounded mechanics, a stronger reviewer for invariant analysis, and the highest-capability available model only for a hard causal deadlock. The user-selected root remains owner unless the user changes it.
